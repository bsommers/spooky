# Phase 11: UI features (milestone v3)

**Goal:** every user-facing operation usable from the UI, accessibly and safely, in both themes. Score/Humanize tasks run only when Phase 8 has landed (capability endpoint reports them); otherwise panels render a "not available" state and their tests are skipped with a recorded reason.

## Screens
| Screen | Operations (HTTP) | Content |
|---|---|---|
| Generate | `generate`, `authors`, `personas` | author + persona selects, input textarea (live char count vs cap), Generate button with busy state, output (plain text, copy button), trace table (filter, modified, ms, metadata counts), banned-phrase and confidentiality indicators (counts only, never matched text), error banner by typed code |
| Ingest / Authors | `ingest`, `authors`, `profile` | ingest form (text paste or file read client-side into text; id, name), author list, stylometric profile view (numbers + simple SVG bars) |
| Personas | `personas` | list/detail, banned phrases, tone fields; read-only |
| Settings | `config get`, theme | provider/model/baseUrl host, API key env var NAME with set/unset status only (server reports boolean), theme switcher, state dir shown read-only, optional API bearer token entry held in memory only |
| Score / Humanize (gated on Phase 8) | `score`, `humanize` | before/after scores, per-feature delta table with bars, iteration history, meaning-guard reverts shown |

## Test matrix
| Tier | Case |
|---|---|
| component | each screen with mocked API (MSW or fetch stub): loading, empty, success, each typed error code, retry |
| component | Generate: cannot submit empty/over-cap input; selects populated from API; trace renders all entries; banned-phrase indicator shows count only |
| security | XSS: model output / persona text / author names / trace metadata containing `<img onerror>`, `<script>`, `javascript:` URLs render as literal text; eslint `react/no-danger` and `no-restricted-syntax` ban `dangerouslySetInnerHTML`, `innerHTML`, `eval`; a test greps `ui/src` for them; no markdown/HTML rendering of model output |
| security | secrets: Settings never displays a key (server returns boolean only); a planted `sk-...` env var -> not in any API response consumed by UI, not in localStorage/sessionStorage/IndexedDB after full flow (Playwright inspects storage), not in `ui/dist` (scan-bundle: entropy + known secret regexes from the confidentiality filter, plus the planted value) |
| security | CSP: server header `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`; Playwright asserts zero CSP violations console events over all screens; no inline `style=` attributes needing `unsafe-inline` (CSS custom properties set via classes/CSSOM) |
| a11y | axe per screen x 2 themes x key states (error, busy): zero violations |
| keyboard | Tab order per screen, visible focus ring (token contrast already tested), Esc closes dialogs, Enter/Space on controls, select/combobox arrow navigation, no keyboard traps, skip-to-content link, live region announces completion/errors |
| visual | Playwright screenshots of every screen x both themes (+ error state for Generate), fixed viewport + 1 mobile width, fonts/animations frozen, deterministic mock API; baselines committed, diff threshold documented |
| e2e | real server + `MockLlmClient`: ingest author -> generate -> output visible and equals API result; offline run (non-localhost blocked) passes |
| parity | UI calls only registry operations; no route used by UI missing from OpenAPI; parity test from Phase 9 extended with a UI-uses-op manifest (`ui/src/api/operations.ts` generated from OpenAPI) |

## Threat/failure model
Model output and corpus text are untrusted (they may contain markup or prompt-injection text): rendered as text only. The browser is an untrusted holder of secrets: the key lives only on the server env; the optional API token is memory-only. A compromised dependency could exfiltrate: CSP `connect-src 'self'`, lockfile, license/audit step. Visual baselines are platform-sensitive: generate in the pinned Playwright container/OS and document.
